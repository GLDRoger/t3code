# Kin rules and what enforces them

Each rule below is one Kin got wrong more than once. A check now refuses the mistake, so a brief or a review doesn't have to repeat it. Lint rules live in `oxlint-plugin-t3code/rules/kin-*.ts` and are switched on for Kin paths in `vite.config.ts`. `vp run check:changed` runs all of them, plus the branch checks.

| Rule                                                                                                                                                                                                                                                                     | Enforced by                                                                                                                                               | When it really is an exception                                                                                     |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| A read that a person reaches returns only what that person sees. A read model takes a required `viewer: KinViewer` (`work/teamView.ts`). Owner-level reads pass `KIN_OWNER_LEVEL` or are named `ownerLevel…`. RPC handlers and MCP tools run no record SQL of their own. | `t3code/kin-viewer-scoped-reads` and the `KinViewer` type                                                                                                 | `// oxlint-disable-next-line t3code/kin-viewer-scoped-reads -- <why>`                                              |
| Owner authority includes co-owners. Ask `mayActAsOwner` in `people/KinAccess.ts`. Where only the owner himself is meant (his private chats, statement notices, managing co-owners), use `isOwnerHimself`. For an agent's own owner, use `ownsAgent`.                     | `t3code/kin-owner-level`: no comparing against the owner's id outside KinAccess                                                                           | the same disable comment, with a reason                                                                            |
| A relay, nudge or notice to a person posts through `KinLevelGate.postTo`, which `KinFloor.admitToPerson` admits. The gate's `post` and the floor's grants are only for the turn's own reply.                                                                             | `t3code/kin-messages-to-people`                                                                                                                           | the chat service, gate, floor, reply bridge and chat toolkit are exempt in `vite.config.ts`                        |
| A server time names the person's zone: the owner's from `ownerZone` (`work/recordRows.ts`), anyone else's from their profile. The owner's zone is read in one place, and an unset zone falls back to the host's zone, never to UTC.                                      | `t3code/kin-zoned-time`                                                                                                                                   | a disable comment with a reason; `MemoryCache` keeps its own read so the prompt can leave out a zone it can't read |
| A branch doesn't drop work that a recently merged PR added.                                                                                                                                                                                                              | `kin branch` step of `check:changed` (`scripts/kin-branch-checks.ts`), which fails when more than 60% of a merged PR's surviving lines in a file are gone | a commit in the branch saying `Supersedes: #N`                                                                     |
| A new Kin migration is numbered one above the base's highest, with no gap and no repeat.                                                                                                                                                                                 | `kin branch` step                                                                                                                                         | none: renumber                                                                                                     |
| The agent instructions' version goes up by exactly one over the base's when their text changes, and stays the same when it doesn't.                                                                                                                                      | `kin branch` step                                                                                                                                         | none: merge the base and set the version                                                                           |
| Copy shared by web and phone lives in `packages/client-runtime`, not in each screen.                                                                                                                                                                                     | review; the client-runtime views (`kinWorkClients.ts` and others)                                                                                         | —                                                                                                                  |

Run `node scripts/kin-branch-checks.ts mine/kin` to run the branch checks on their own.

## Judgment only

No check covers these. Decide them in review:

- Workers and local workers act as the owner himself (`isOwnerHimself`), not as any co-owner, because they run on his host.
- Goals are visible to the whole team by design (`goalsNow` takes no viewer).
- `pulse/senses/money.ts` decides when an invoice is overdue with its own chase grace; it doesn't use `owedInvoices`. Keep the two in step by hand.
- A client screen uses the device's zone for when things happened, since the device belongs to its viewer. Company due days use the owner's zone through `kinZonedDayStart`.
- A loose check-in shows "around" a time. `KinSchedules.isAround` decides which ones are loose.
- A header count and the list under it come from separate SQL in a few places: the Work summary and the client page's owed counts. They use the same predicate, so a change to one must change the other.
